# 发布与更新

本文描述 Book 的发版约定、R2 目录结构与 CI 流程。当前版本以 `pubspec.yaml` 为准。

## 1. 域名

| 项 | 值 |
| --- | --- |
| APK / 版本信息 | `apk.book.hunau.fmcoral.com`（Cloudflare R2 公共桶 + 自定义域名） |
| 官网 | `book.hunau.fmcoral.com`（GitHub Pages，仓库根目录 `index.html`） |
| 反馈接口 | `feedback.hunau.fmcoral.com` |

## 2. R2 目录结构

桶名由 CI 变量 `R2_BUCKET_NAME` 指定，公共读，不开放写：

```
latest/
├── version.json          检查更新读取
├── app-release.apk       arm64 包，应用内下载
└── announcements.json    软件公告（手动上传，非 CI 产物）
```

`announcements.json` 规则见 [公告编辑规则](announcements.md)；该文件不存在时 App 显示「暂无公告」。

## 3. version.json

由 CI 在发版时生成，结构固定：

```json
{"version": "1.2.2", "notes": "1. 修复……\n2. 新增……"}
```

- `version` 取自 tag（去掉前缀 `v`）。
- `notes` 优先读取 `docs/release-notes/<version>.txt`，否则用 commit 正文，最后兜底「例行更新」。
- 因此**必须有对应的 notes 文件**，不要依赖 commit 标题。

## 4. 发版流程

1. 修改 `pubspec.yaml` 版本号，格式 `x.y.z+build`，如 `1.2.2+25`。
2. 新增 `docs/release-notes/<x.y.z>.txt`，编号列表，一行一条。
3. 在 `docs/CHANGELOG.md` 顶部补同版本记录。
4. 本地校验：`flutter analyze`；必要时 `flutter build apk --debug --target-platform android-arm64`。
5. 单个提交 + 单个 tag：`git tag vX.Y.Z`。
6. 推送：`git push origin main vX.Y.Z`。
7. CI 构建成功后会更新 R2 的 `latest/version.json` 与 `app-release.apk`。

只推 `main` 不发版时，不要打 tag。

## 5. CI 行为

- 触发条件：推送 `v*` 或 `x.y.z` 形式的 tag；也支持手动 `workflow_dispatch`（可填 notes）。
- 构建：`flutter build apk --release --target-platform android-arm64 --split-per-abi`，失败自动重试 3 次。
- 上传：`dist/app-arm64-v8a-release.apk` 重命名为 `app-release.apk`，与 `version.json` 一起写入 `latest/`。
- 缓存：`version.json`、APK 均带 `max-age=60`；配置了 Cloudflare 凭据时会主动清缓存。
- 发布强依赖 R2：凭据缺失或上传失败会让本次 Action 失败，不会静默跳过。

### 版本号编码

CI 保留 `--split-per-abi`，Flutter 会把 versionCode 编码为 `build*1000+ABI`（arm64 对应 2）：

| build | arm64 versionCode |
| --- | --- |
| 23 | 23002 |
| 24 | 24002 |
| 25 | 25002 |

不要改成不带 `--split-per-abi` 的构建方式，否则 versionCode 会回落，系统判定为降级包，用户无法覆盖安装。

## 6. 发布后自检

- [ ] `https://apk.book.hunau.fmcoral.com/latest/version.json` 的 `version` 与新 tag 一致
- [ ] `notes` 内容来自 `docs/release-notes/<版本>.txt`，不是 commit 标题
- [ ] `app-release.apk` 可下载，安装后「关于」显示新版本号
- [ ] App 内「检查更新」能进入更新说明页并下载
- [ ] 需要公告时，`latest/announcements.json` 已更新

## 7. 网络提示

国内直连 GitHub 推送可能超时。若 `git push` 报 `Failed to connect to github.com port 443`，可临时走本机代理，仅对本次命令生效：

```powershell
git -c http.proxy=http://127.0.0.1:7890 -c https.proxy=http://127.0.0.1:7890 push origin main vX.Y.Z
```
