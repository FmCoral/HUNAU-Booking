# 软件公告编辑规则

App 内「公告」是软件自己的公告，与学习通通知无关。公告内容不打包进 APK，改完上传即可生效，无需发版。

## 1. 生效流程

1. 在本地编辑 `announcements.json`（结构见下文）。
2. 上传到 R2 公共桶，路径固定为 `latest/announcements.json`。
3. App 打开公告页或下拉刷新，即可看到最新内容。

完整地址：

```
https://apk.book.hunau.fmcoral.com/latest/announcements.json
```

文件不存在（404）时，App 显示「暂无公告」，不会报错。

## 2. 整体结构

```json
{
  "items": [
    {
      "id": "20261127-example",
      "title": "标题",
      "content": "第一行\n第二行",
      "publishedAt": "2026-11-27 10:00",
      "type": "notice",
      "pinned": false
    }
  ]
}
```

- 顶层必须是对象，且包含 `items` 数组；没有公告时写 `{"items": []}`。
- 数组顺序不影响展示，App 会自行排序。
- 文件必须是 **UTF-8 无 BOM** 的纯 JSON，不能写注释，不能有尾随逗号。

## 3. 字段说明

| 字段 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | 字符串 | 是 | — | 唯一标识，不可重复、不可复用；建议 `日期-短名`，如 `20261127-dorm` |
| `title` | 字符串 | 是 | — | 标题，列表单行显示，建议不超过 20 字，超长会省略 |
| `content` | 字符串 | 是 | — | 正文，用 `\n` 换行；列表显示前两行摘要，详情页显示全文 |
| `publishedAt` | 字符串 | 是 | — | 发布时间，格式 `YYYY-MM-DD HH:mm`，按字典序倒序排列 |
| `type` | 字符串 | 否 | `notice` | `notice` / `feature` / `fix` / `warning`，只影响图标和颜色 |
| `pinned` | 布尔 | 否 | `false` | `true` 置顶；置顶内部仍按时间倒序 |
| `minVersion` | 字符串 | 否 | — | 当前 App 版本 ≥ 该值才显示（含该版本） |
| `maxVersion` | 字符串 | 否 | — | 当前 App 版本 ≤ 该值才显示（含该版本） |
| `versions` | 字符串数组 | 否 | — | 精确版本白名单；非空时忽略 `minVersion` / `maxVersion` |
| `link` | 对象 | 否 | — | 详情页底部按钮，`{"text": "查看详情", "url": "https://..."}` |

### 3.1 id 规则

- 必须唯一；删除公告后不要再用旧 `id`，否则老用户本地已读标记可能串号。
- 建议格式：`YYYYMMDD-英文短名`，只用字母、数字、短横线。

### 3.2 title 规则

- 单行，不要放换行符。
- 建议 8–20 字，把结论放前面，如「宿舍电费充值已上线」。
- 不要写「公告」「通知」之类前缀，列表本身已在公告页。

### 3.3 content 规则

- 换行必须写成 `\n`，不能直接回车换行（JSON 不允许裸换行）。
- 列表页只显示前两行，重要信息放前两行。
- 需要引号时用 `\"` 转义；需要反斜杠时用 `\\`。
- 建议单条正文不超过 300 字，长文改用 `link` 跳转。

### 3.4 publishedAt 规则

- 必须补零，例如 `2026-11-27 09:05`，不能写 `2026-11-27 9:5`。
- 排序按字符串倒序，格式不统一会导致顺序错乱。
- 修改旧公告内容时同步更新该时间，让它回到列表顶部。

### 3.5 type 取值

| 值 | 含义 | 使用场景 |
| --- | --- | --- |
| `notice` | 普通通知 | 默认，一般说明 |
| `feature` | 新功能 | 功能上线、体验改进 |
| `fix` | 修复 | 问题修复说明 |
| `warning` | 重要提醒 | 停服、维护、需要用户立即处理的事项 |

### 3.6 link 规则

```json
"link": { "text": "查看详情", "url": "https://book.hunau.fmcoral.com/" }
```

- `text` 建议 2–6 字，如「查看详情」「前往官网」。
- `url` 必须是完整的 `https://` 地址，App 用外部浏览器打开。
- 不需要按钮时整个 `link` 字段省略即可。

## 4. 版本定向

版本匹配优先级：`versions`（精确命中）> `minVersion` / `maxVersion`（区间）> 都不写（所有版本可见）。

版本按数字段逐段比较，`1.1.10 > 1.1.9`；忽略 build 号，只看 `x.y.z`。

| 想实现 | 写法 |
| --- | --- |
| 所有版本可见 | 不写版本字段 |
| 某版本及以后可见 | `"minVersion": "1.2.0"` |
| 某版本及以前可见 | `"maxVersion": "1.2.1"` |
| 仅几个指定版本可见 | `"versions": ["1.1.7", "1.1.8"]` |
| 某区间可见 | 同时写 `minVersion` 与 `maxVersion` |

当前 App 版本可在「我 → 关于」查看。

## 5. 常见编辑场景

**新增一条公告**：在 `items` 数组里加一个对象，填好必填字段，`publishedAt` 用当前时间。

**修改公告**：按 `id` 找到对应对象，改内容并更新 `publishedAt`。

**下线公告**：删除该对象（含前一个对象末尾的逗号处理），不要把 `title` 设为空字符串。

**临时置顶**：给该条加 `"pinned": true`，多条置顶时仍按时间倒序。

**只给新版本看**：加 `"minVersion": "当前最新版本"`。

**旧版本专属通知**：用 `"maxVersion"` 限定上限。

## 6. 上传与生效

1. R2 桶内进入 `latest/` 目录，覆盖上传 `announcements.json`。
2. 确认对象可公开访问：浏览器直接打开公告地址应返回 JSON 原文，而不是下载或 403。
3. App 内下拉刷新公告页；已打开的详情页需返回列表再进入才会更新。
4. 若内容未变，检查是否传到了 `latest/announcements.json`（大小写、目录都不能错）。

请求会附带时间戳参数，正常情况无需手动清缓存。

## 7. 自测清单

- [ ] 浏览器直接打开公告 URL 能看到 JSON
- [ ] 公告页能拉到数据，置顶条目在最前
- [ ] 版本定向条目在预期版本上出现 / 不出现
- [ ] 含 `\n` 的正文在列表显示两行摘要，详情页换行正常
- [ ] `link` 按钮能跳转到正确地址
- [ ] 中文无乱码（文件为 UTF-8）

## 8. 故障排查

| 现象 | 可能原因 |
| --- | --- |
| 公告页显示「暂无公告」且 URL 打不开 | 文件未上传 / 路径或大小写错误 / 桶未公开 |
| 公告页显示「暂无公告」但 URL 正常 | JSON 语法错误导致解析失败，或顶层缺少 `items` |
| 某条公告不显示 | 被 `minVersion` / `maxVersion` / `versions` 过滤，或 `id`、`title`、`content`、`publishedAt` 缺失 |
| 顺序不对 | `publishedAt` 格式不统一或未补零 |
| 正文中文乱码 | 文件不是 UTF-8，或带 BOM |
| 换行失效 | 正文里直接回车，应该写 `\n` |
| 链接打不开 | `url` 缺少协议头，或不是 `https://` |

## 9. 完整模板

```json
{
  "items": [
    {
      "id": "20261127-update",
      "title": "新版本已发布",
      "content": "本次更新修复了若干问题。\n可在「关于 → 检查更新」升级。",
      "publishedAt": "2026-11-27 12:00",
      "type": "feature",
      "pinned": true,
      "minVersion": "1.2.0",
      "link": {
        "text": "查看详情",
        "url": "https://book.hunau.fmcoral.com/"
      }
    },
    {
      "id": "20261127-notice",
      "title": "系统维护通知",
      "content": "11 月 30 日 00:00–02:00 校园卡服务维护，期间充值暂停。",
      "publishedAt": "2026-11-27 09:00",
      "type": "warning"
    }
  ]
}
```

可直接参考 `docs/announcements.example.json` 与 `docs/announcements.test.json`，改完上传即可。
